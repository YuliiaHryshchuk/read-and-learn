# Веб-приложение для чтения по методу Франка

Дата: 17 сентября 2026 года.  
Обновлено: 21 сентября 2026 года.  
Статус: базовые решения для MVP. Документ фиксирует договорённости, а не наличие готовой реализации.

## 1. Цель

Пользователь вводит текст на испанском и получает материал для чтения по методу Франка: перевод и пояснения на русском внутри адаптированных отрывков, чередующихся с теми же отрывками без подсказок. Готовый материал можно сохранить в личную библиотеку и открыть позже.

## 2. Сценарий MVP

1. Пользователь входит в аккаунт и открывает страницу обработки текста.
2. Вставляет испанский текст в текстовое поле и запускает адаптацию.
3. Приложение отправляет текст во внешний ИИ API и показывает состояние обработки.
4. После обработки пользователь читает результат.
5. По желанию сохраняет материал с названием в личную библиотеку.
6. В библиотеке открывает ранее сохранённые материалы или удаляет их.

Сохранение в библиотеку выполняется по действию пользователя. При повторном открытии сохранённого материала новый запрос к ИИ не требуется.

## 3. Формат результата

Результат состоит из последовательных блоков. Каждый блок включает:

- **Адаптированный отрывок:** испанский текст, разбитый на небольшие части, с переводом и необходимыми пояснениями на русском в скобках.
- **Неадаптированный отрывок:** тот же испанский отрывок без переводов и подсказок, сразу после адаптированного.

Исходный текст должен сохраняться без пересказа, сокращений и исправлений. Соответствие оригиналу проверяется программно; конкретный способ проверки определяется при реализации.

Ответ ИИ запрашивается в структурированном формате с блоками оригинала, перевода и пояснений. Сервер проверяет структуру, а фронтенд формирует отображение. Точная схема ответа и правила размера отрывков будут уточнены на примерах.

### Отображение материала

- Интерфейс приложения и все элементы управления — на английском. В MVP содержимое материала остаётся испанским с русским переводом и пояснениями.
- Сначала показывается исходный текст целиком, затем пронумерованные фрагменты. Каждый фрагмент имеет собственную рамку и содержит исходный отрывок, перевод и подробное объяснение.
- При первом открытии результата развёрнут первый фрагмент, остальные свёрнуты. У свёрнутого фрагмента видны номер и начало исходного текста; нажатие на текст или стрелку раскрывает его. Есть команды раскрыть и свернуть все фрагменты.
- В раскрытом фрагменте перевод изначально скрыт, объяснение открыто. Перевод и объяснение можно показывать и скрывать независимо. Для перевода используются тот же цвет и шрифт, что и для исходного отрывка.
- Прокрутка допускается внутри длинного объяснения. Его высота ограничивается доступной высотой экрана с учётом остальной части фрагмента и рассчитана минимум на три строки. Исходный отрывок и перевод показываются целиком.
- Для интерфейса приоритетен настольный экран, но компоновка должна оставаться пригодной для узких экранов.

## 4. Принятый стек

| Компонент | Решение | Назначение |
|---|---|---|
| Язык приложения | TypeScript | Общий язык для интерфейса и серверной части |
| Веб-фреймворк | Next.js с React | Страницы приложения и серверные обработчики |
| Стили интерфейса | SCSS и SCSS Modules | Глобальные стили и стили компонентов |
| База данных | PostgreSQL | Хранение сохранённых материалов и связи с владельцами |
| Работа с БД | Prisma | Доступ к данным и миграции структуры БД |
| Обработка текста | Внешний ИИ API | Перевод и пояснения; провайдер и модель пока не выбраны |
| Авторизация | Готовое решение, выбор отложен | Вход в аккаунт и идентификация пользователя |
| Локальный запуск | Docker Compose | Воспроизводимый запуск приложения и БД |

Отдельный Python-сервис для текущего объёма задач не требуется. Запуск собственной модели не планируется.

## 5. Архитектура и доступ к данным

```text
Браузер (React)
       |
       v
Сервер приложения (Next.js)
       |                 |
       v                 v
PostgreSQL         Внешний ИИ API
через Prisma
```

Запросы к ИИ и БД выполняются на сервере. Сервер проверяет владельца материала при чтении, сохранении и удалении. Пользователь имеет доступ только к своим материалам.

Ключ ИИ API и параметры доступа к БД передаются через переменные окружения. Для локальной работы используется `.env`, исключённый из Git. Секреты не встраиваются в Docker-образ и не передаются в браузер. В репозитории хранится `.env.example` с названиями переменных и безопасными примерами.

## 6. Хранимые данные

Для сохранённого материала необходимы:

- идентификатор материала и идентификатор владельца;
- название;
- исходный текст;
- исходный язык и язык перевода;
- готовые структурированные блоки адаптации;
- дата создания.

В MVP доступна только пара испанский → русский, но языки хранятся как отдельные параметры для последующего расширения.

Способ хранения учётных записей зависит от выбранного решения авторизации. Хранение несохранённых результатов и технических записей обработки пока не определено.

## 7. Docker и локальная разработка

Предусмотрены два контейнера:

- приложение Next.js;
- PostgreSQL с отдельным Docker volume для сохранения данных между перезапусками.

В поставку проекта должны входить `Dockerfile`, `compose.yaml`, `.env.example` и инструкция запуска. После заполнения `.env` целевой запуск:

```bash
docker compose up --build
```

Приложение должно быть доступно по адресу `http://localhost:3000`. Установка Node.js и PostgreSQL на компьютер не требуется; нужны Docker с Compose, интернет и ключ выбранного ИИ API.

Для разработки предусматривается обновление приложения при изменении кода без пересборки образа после каждой правки. Применение миграций Prisma включается в процедуру запуска; конкретный механизм определяется при реализации.

Названия коммитов и их описания в Git пишутся на английском языке.

Контейнер приложения обращается к внешнему ИИ API через исходящие HTTPS-запросы. Дополнительные входящие порты для этих запросов не нужны. Доступ зависит от сетевых настроек компьютера, VPN и firewall.

## 8. Ограничения и обработка ошибок

Для MVP исходный текст ограничен одновременно 300 словами и 3000 символами. Текст, превышающий хотя бы один из лимитов, не отправляется на обработку. Интерфейс показывает оба ограничения, а сервер проверяет их повторно до обращения к ИИ API. Точные правила подсчёта слов и символов определяются при реализации.

Ограничения количества запросов для контроля стоимости и времени обработки пока не согласованы.

Интерфейс должен показывать состояние обработки и понятную ошибку при недоступности API, превышении лимита или некорректном ответе. Ошибка обработки не должна отображаться как успешная адаптация.

Необходимость фоновой очереди определяется после замеров времени обработки. Отдельный обработчик фоновых задач пока не включён в принятый стек.

## 9. Развитие после MVP

- Выбор исходного языка и языка перевода вместо фиксированной пары испанский → русский.
- Загрузка текстовых файлов.
- Загрузка изображений с текстом и извлечение текста для адаптации.

Форматы файлов, ограничения размера, распознавание текста, файловое хранилище и сроки хранения загруженных файлов будут определены отдельно. В MVP загрузки файлов нет.

## 10. Открытые решения

- Провайдер ИИ API и модель: выбрать после сравнения качества на нескольких испанских текстах.
- Образец желаемого результата: согласовать подробность пояснений и размер отрывков.
- Способ входа и сервис авторизации.
- Правила подсчёта слов и символов; лимиты частоты запросов и расходов на API.
- Точная схема структурированного ответа ИИ и правила его проверки.
- Хостинг для опубликованной версии и параметры производственного развёртывания.
- Правила хранения несохранённых результатов и удаления данных.

## 11. Критерии готовности MVP

- Проект запускается локально через Docker Compose по инструкции.
- Пользователь может войти в аккаунт, отправить испанский текст и получить адаптацию с русским переводом и пояснениями.
- Адаптированные отрывки чередуются с соответствующими оригинальными отрывками без подсказок.
- Материал можно сохранить, открыть из библиотеки без повторной генерации и удалить.
- Материалы недоступны другим пользователям.
- Сохранённые материалы остаются доступны после перезапуска контейнеров при сохранённом volume БД.
- Ключ API отсутствует в клиентском коде, репозитории и Docker-образе.
- Пользователь видит состояние обработки и сообщения об ошибках.

Ближайший шаг: согласовать несколько эталонных примеров адаптации, затем выбрать ИИ API и уточнить контракт ответа.
